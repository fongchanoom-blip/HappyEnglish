## 一、核心愿景：从工具到智能体的跃迁

### 当前状态 vs 目标状态

| 维度 | 当前（工具模式） | 目标（智能体模式） |
|------|-----------------|-------------------|
| 交互方式 | 用户提问 → AI 回答 | AI 主动观察 → 引导学习 |
| 学习模式 | 静态内容交付 | 动态策略适配 |
| 个性化 | 有限规则 | 基于完整学习上下文 |
| 主动性 | 用户发起 | AI 发起（适当时机） | 
| 关系 | 服务提供者 | 学习伙伴 |

### 智能体核心定义

> **新一代智能体** = 具备记忆、推理、规划能力的 AI 系统，能主动识别学习机会、适时引导、在适当时机退后，让学生在自主探索与适时支持间找到平衡。

## 四、苏格拉底式学习（LLM 推理能力应用）

### 核心原则：永远给路径，不给答案

```
┌─────────────────────────────────────────────────────────────┐
│  苏格拉底问题树示例 (单词: "ubiquitous")                     │
│                                                             │
│  Q1: "这个词对你来说是什么意思？"                            │
│  ↓                                                          │
│  Q2: "如果某物无处不在，前缀会给你什么提示？"                │
│  ↓                                                          │
│  Q3: "你提到它和'omni'有关，为什么不是'omniquitous'？"       │
│  ↓                                                          │
│  Q4: "现在用它造一个描述非数字事物的句子"                    │
│  ↓                                                          │
│  ← 学生自己达到理解                                          │
└─────────────────────────────────────────────────────────────┘
```

### 语法的 Chain-of-Thought 推理

```
问题: "If I was you, I would go." (虚拟语气错误)

Socratic 推理轨迹:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
T: "'if' 从句表达了什么语气？"
S: "假设性的东西。"
T: "正确。现实和假设一样吗？"
S: "不是，我不是 'you'，所以不同。"
T: "当现实和假设不同时，我们称为什么语法？"
S: "虚拟语气？"
T: "很好。虚拟语气中，'were' 后面跟什么形式而不是 'was'？"
S: "Were - 总是。"
T: "那原句应该怎么读？"
S: "If I were you..."
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### 故意错误注入（促进性矛盾）

```
┌──────────────────────────────────────────────────────────────┐
│  错误注入协议                                                 │
│                                                              │
│  Step 1: 呈现错误示例                                        │
│  "The team have finished their homework."                    │
│                                                              │
│  Step 2: 探测学生识别能力                                    │
│  "这听起来对吗？"                                            │
│                                                              │
│  Step 3: 引导诊断推理                                        │
│  "这里决定动词一致的是什么——'team' 还是 'their'？"           │
│                                                              │
│  Step 4: 强制元分析                                          │
│  "为什么有人这样写？代表什么错误模式？"                       │
│                                                              │
│  Step 5: 迁移到生产                                          │
│  "现在找出并纠正同一错误: 'The data show a significant...'" │
└──────────────────────────────────────────────────────────────┘
```

### 苏格拉底问题分类

| 策略 | 示例 | 认知目标 |
|------|------|---------|
| **定义探查** | "这个词的词根告诉你什么？" | 词源识别 |
| **上下文推断** | "在什么场景下你会*不用*这个词？" | 边界理解 |
| **类比迁移** | "更简单的同义词是什么？什么时候不行？" | 精确度认知 |
| **对比挑战** | "这个词比 'ubiquitous' 强还是弱？" | 细微差别校准 |
| **生产提示** | "写一个这个词是关键链接的句子" | 主动编码 |

## 五、情感连接设计

### 记忆作为情感纽带

**长期记忆系统**：
- **里程碑回忆**：AI 自然引用过去成就 — "上周你还在这个概念上挣扎，现在你独立应用了——这是真正的成长"
- **偏好学习**：不仅记录*学什么*，还记录*怎么学*
- **失败遗忘**：故意降低失败尝试的记忆权重，强调进步而非过去

### AI 成长模型

| 学生进步 | AI 进化 |
|---------|---------|
| 初学者 | AI 鼓励更多，使用简单语言，庆祝小胜利 |
| 中级 | AI 成为"同伴教练"——更直接反馈，期待更高 |
| 高级 | AI 作为思维碰撞伙伴——挑战、质疑假设 |

**行为变化信号**：
- AI 语气从 "我来帮你" 变为 "让我给你看一些有趣的东西"
- AI 开始问学生意见："你觉得这个方法怎么样？"
- AI 引用共同"内部知识"——随着时间建立的笑话、参考

### 动机架构

**通用表扬的问题**：简单的 "做得好！" 不能建立联系，学生能感觉到是脚本化的。

**有效反馈原则**：

1. **具体进展认可**
   - 不只是 "正确"，而是命名*什么*做得好
   - "你发现了自己推理中的缺陷——这是分析成熟度发展的标志"

2. **挣扎验证**
   - "这很难。这实际上是好事——意味着你在学真正的东西"
   - 正常化困难，消除羞耻感

3. **代理肯定**
   - "你选择回来再试一次。这是最重要的决定"
   - 关注选择，不只是结果

4. **未来预演**
   - "想象一下向弟弟妹妹解释这个——这就是你理解得有多好"

## 七、实时 AI 交互策略

### 延迟与质量权衡

**核心问题**：需要 <500ms 感知延迟，同时提供实质性 AI 响应。

**解决方案：渐进式披露架构**

```
用户输入
    ↓
Tier 0: 即时响应 (<100ms)
- 本地规则、模板、缓存数据
- "做得好！""再试一次"、基本反馈

    ↓ (并行)
Tier 1: 快速 AI (<300ms)
- 预计算已知单词解释
- 简单跟进问题

    ↓ (如需要)
Tier 2: 完整 AI 响应 (1-3s)
- 深度分析、词源、记忆技巧
- 流式输出立即开始
```

### 分层 AI 策略

| 查询类型 | 示例 | 响应时间 | 策略 |
|----------|------|----------|------|
| 即时 | "正确！" | <50ms | 本地音频 + emoji |
| 快速 | "人字怎么记？" | <300ms | 预计算 + 缓存 |
| 中等 | "人字的由来" | <800ms | 模板 + 流式 |
| 深度 | "为什么学习汉字重要？" | 2-3s | 完整 AI + 流式 |

### 流式输出设计

像 Duolingo 一样的逐字流式传输：
1. 显示缓存内容（立即）
2. 同时流式传输深度内容
3. 用户感知流式输出比等待完整响应更快

## 八、Agent 主动干预设计

### 干预触发条件

| 机会类型 | 检测信号 | Agent 响应 |
|---------|---------|-----------|
| **间隔重复到期** | 距上次曝光时间超过最佳间隔 | "嘿，让我们复习这几个字！" |
| **混淆模式** | 同一错误 3+ 次跨会话 | "我发现这几节课总是搞混" |
| **动力机会** | 学生连续学习 5+ 天，表现出参与 | "你已经连续学习了5天！要不要挑战一下新单词？" |
| **疲劳信号** | 响应延迟增加，准确率下降 | "休息一下吧，明天我们继续" |
| **跨会话迁移** | 新单词与已知弱字共享部首 | "你之前学得很好，这个就不难啦" |

### 干预决策树

```
学生是否在挣扎？ ──是──→ 是已知模式？ ──是──→ 应用已验证策略
                    │
                    否──→ 诊断 + 尝试新方法 + 记录结果
                    │
                    否──→ 学生是否不投入？ ──是──→ 低压力鼓励
                                      │
                                      否──→ 继续当前路径
```

### 交互边界

**介入时机**：
- 明确误解会加重时（如混淆部首）
- 学生表现出沮丧信号
- 最优学习时机（间隔重复时间）
- 会话即将以负面结束

**退后时机**：
- 学生处于心流状态（不要打断）
- 他们无需帮助也能进步（信任系统）
- 多次干预失败（承认并暂停）
- 明确要求独处

## 九、教育学原理应用

### 掌握学习（Mastery Learning）

传统掌握学习要求学生在进入下一步前达到 ~85% 熟练度。LLM 可以通过以下方式实现：

- 将概念分解为微学习目标（3-5 分钟节点）
- 部署自适应测验，精确找出理解中断的位置
- 使用贝叶斯知识追踪为每个学生每个概念建模掌握概率

```
学生完成任务 → LLM 评估响应 →
  如果 掌握概率 < 0.85: 提供针对性脚手架
  如果 >= 0.85 且先决条件已掌握: 前进
```

### 间隔重复优化

| 学生表现 | 间隔策略 |
|---------|---------|
| 强记忆 | 1天 → 4天 → 2周 → 1月 → 3月 |
| 弱记忆 | 15分钟 → 2小时 → 1天 → 3天 → 1周 |
| 检测到误解 | 压缩间隔，改变表示方式 |

**LLM 增强**：不仅固定间隔，还能：
- 分析学生*为什么*挣扎
- 生成语义变化的问题（相同概念，不同措辞）
- 根据实时信心信号动态调整

### 误解检测

这是 AI 可以超越人类能力的领域——在误解固化前识别它们。

**模式检测**：
- 分析不正确响应的语义以分类错误类型
- 常见误解有"特征"（例如，认为 0.5 < 0.3 的学生揭示了特定的数轴误解）
- 将响应向量与已知误解嵌入进行比较

## 十、安全与伦理设计

### 幻觉缓解

| 风险 | 缓解策略 |
|------|---------|
| 静态内容 | 使用预录音频，消除发音幻觉风险 |
| 错误词义 | 实现"验证层"——所有内容由教育者策划 |
| 过期信息 | 版本控制带日期；6个月后自动提示刷新 |
| 信心信号 | 始终以"记住..."或"这是..."为前缀，建立事实基调 |

### 隐私与数据保护

| 要求 | 实现 |
|------|------|
| 数据最小化 | 仅收集学习进度和会话时间戳，无个人标识符 |
| 家长同意 | 需要家长账户验证才能存储数据 |
| 静态加密 | 本地存储使用 AES-256；网络调用使用 HTTPS |
| 删除权 | 提供"重置进度"功能；账户解除时删除数据 |
| 透明度 | 首次使用前显示隐私声明 |

### 防止过度依赖

| 设计原则 | 实现 |
|---------|------|
| 认知负荷平衡 | 限制会话时长（例如，每天最多 15 分钟） |
| 脚手架消退 | 3 次正确答案后，将 AI 提示减少 50% |
| 强调主动回忆 | 提供答案前先提示"先自己试试" |
| 鼓励外部学习 | 复杂问题建议"问问老师/家长" |
| 进展可视化 | 显示学习旅程，而非对 AI 的依赖 |

### 教育中立性

- **内容过滤器**：所有文本/发音预先批准
- **时间控制**：每 15 分钟强制休息
- **家长仪表板**：实时进度监控
- **年龄适当设计**：无广告、无外部链接
- **紧急协议**："报告问题"按钮（连接人工支持，非 AI）

## 十二、关键设计原则总结

1. **记忆是护城河**：设计良好的持久记忆系统创造真正的个性化，这是竞争对手难以复制的。

2. **模式干预，不实例干预**：一次错误 = 无动作。三次类似错误 = 干预。显著减少噪音。

3. **优雅降级设计**：如果 agent 不确定，默认保守动作（不干预）。

4. **让学生感受主导权**：agent 的工作是支持，而非主导每一次互动。学生能动性对长期动机至关重要。

5. **衡量干预有效性**：跟踪哪些干预与掌握提升相关，并相应调整系统。

6. **从工具到伙伴**：从等待问题到看到困惑并干预，看到掌握并前进，看到沮丧并适应。
