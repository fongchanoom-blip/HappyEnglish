## 二、架构决策矩阵

### 前端架构选择

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| Vue3 CDN（当前） | 零构建门槛、快速迭代 | 代码组织受限、无类型检查 | 临时阶段 |
| Vue3 + Vite | 开发体验好、TypeScript支持 | 构建流程增加 | **推荐升级** |
| React + Next.js | 生态丰富、SSR支持 | 学习成本略高 | 需SEO时 |

**推荐**：从 Vue3 CDN 升级到 **Vue3 + Vite**，原因：
- 词库 1675 个词汇需要更好的代码组织
- TypeScript 能保证词汇匹配逻辑的类型安全
- 构建后体积更小

### 数据存储架构

**保持 IndexedDB**，增加云端同步能力：
- 词汇数据 + 学习记录 = 约 2-5MB，IndexedDB 完美支持
- 用户学习记录需要跨设备同步（家长/老师查看）
- 建议：本地 IndexedDB + 云端存储用户进度

### API 设计

**推荐**：RESTful API + BFF 层
- 后端服务封装 Minimax API 调用（保护 API Key）
- `/api/words` - 词汇查询
- `/api/progress` - 学习进度
- `/api/report` - AI 学习报告生成
- 统一加鉴权（JWT 或简单 Token）

---

## 三、AI 服务架构

### 调用模式

| 功能 | 调用模式 | 理由 |
|------|---------|------|
| AI学习报告 | 异步（后台生成） | 非即时需求，可缓存 |
| 智能错题讲解 | 实时 + 预生成 | 高频使用，需快速响应 |
| 语境记忆生成 | 异步 + 批量 | 预生成可减少实时压力 |
| 口语陪练 | 实时 | 需要即时反馈 |

### 分层缓存架构

```
L1: 内存缓存（用户会话内）- TTL: 会话周期
L2: 本地存储（IndexedDB）- TTL: 7天
L3: 服务器缓存 - TTL: 30天
```

### 降级方案

```
L0: 完整AI能力（Minimax正常）
L1: 本地预置内容（模板 + 规则引擎）
L2: 纯本地模式（无网络依赖）
```

## 四、部署策略

| 平台 | 优点 | 适用场景 |
|------|------|----------|
| **Vercel** | 自动部署、CDN边缘、免费额度 | 静态前端首选 |
| **Railway** | 后端 + 数据库一体 | 需要后端时 |
| **Cloudflare Pages** | 全球CDN、Workers边缘计算 | 高性能需求 |

**推荐**：**Vercel 前端** + **Railway 后端**（如需后端）

---

## 五、架构演进路线

### 阶段一（当前 → 短期）
```
静态部署 (Vercel/CDN) + 前端直连 Minimax
```
- 保持简单，快速验证

### 阶段二（6个月后，如需扩展）
```
Vercel (前端) + Railway (Node.js BFF) + PostgreSQL
           ↓
      Minimax API
```
- 后端统一处理 AI 调用、保护密钥
- PostgreSQL 存储用户学习记录（支持跨设备）
- 支持家长/老师查看学习报告

## 六、性能目标

| 指标 | 目标值 | 用户感知 |
|------|--------|---------|
| 首屏加载（首次） | < 2秒 | "一打开就用" |
| 再次打开 | < 500ms | "秒开" |
| 操作响应 | < 100ms | "跟手" |
| AI 报告生成 | < 3秒 | "等一下就好" |

---

## 七、核心结论

1. **前端升级**：从 Vue3 CDN 升级到 Vue3 + Vite
2. **存储保持**：IndexedDB 本地为主，适时增加云端同步
3. **AI 分层**：实时 + 异步分离，三级降级保障
4. **部署简单**：Vercel 前端 + 可选后端
