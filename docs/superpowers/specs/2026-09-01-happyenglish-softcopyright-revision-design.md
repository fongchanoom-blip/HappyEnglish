## 3. 独创性如何体现（应对"模板化"打回的核心）

### 3.1 关键策略：从代码里"挖出有血有肉的细节"而非泛泛而谈

每个创新点都要回答三个问题：
1. **是什么**（定义）
2. **怎么实现**（真实代码 + 流程图）
3. **为什么这么设计**（设计动机 / 对比竞品 / 效果数据）

### 3.2 6 个 P0 重点创新点（详细写，占说明书 70% 篇幅）

#### P0-1：MCP 服务器实现（独家亮点）
- **文件**：[mcp-server/minimax-server.js](D:/claude%20code/HappyEnglish/mcp-server/minimax-server.js)
- **协议**：Model Context Protocol（2024-2025 新兴的 LLM 工具调用协议）
- **设计动机**：解耦 AI 调用与业务逻辑、安全沙箱、可扩展
- **内容**：`tools/list` 注册 `minimax_chat` 工具，`tools/call` 转发到 MiniMax API
- **独家写法**：与 Function Calling 对比，说明为什么选择 MCP

#### P0-2：9 级艾宾浩斯间隔复习算法
- **文件**：[assets/js/app.js:503-507](D:/claude%20code/HappyEnglish/assets/js/app.js#L503-L507)
- **间隔序列**：`[0, 1分钟, 5分钟, 30分钟, 1天, 3天, 7天, 14天, 30天]`
- **差异化**：前 3 级针对首次接触的瞬时巩固，跳过短期记忆高峰
- **独家写法**：对比传统 5 级间隔（1/2/4/7/15 天固定）

#### P0-3：30 题批量测试模式（3 组 × 10 题）
- **文件**：[index.html:613, 736](D:/claude%20code/HappyEnglish/index.html#L613)
- **业务模式**：3 组连续测试，每组 10 题，总计 30 题
- **设计动机**：避免单次大量题目的疲劳，每组后即时反馈
- **独家写法**：对比"10 题随机 / 30 题一次性"两种模式的优劣

#### P0-4：AI Prompt 工程化设计（5 段式输出）
- **文件**：[api/ai-report.js:138-174](D:/claude%20code/HappyEnglish/api/ai-report.js#L138-L174)
- **Prompt 结构**：用户数据 + 5 段 Markdown 输出（概览/趋势/分析/目标/激励）
- **设计动机**：结构化输出便于前端解析与展示
- **独家写法**：解释 prompt 中"薄弱词上下文"的巧思（关联 `vocabulary.json`）

#### P0-5：错题根因 AI 分析 prompt
- **文件**：[index.html:762-774](D:/claude%20code/HappyEnglish/index.html#L762-L774)
- **Prompt 结构**：错误列表 + 三段分析（原因/技巧/复习建议）
- **设计动机**：教育心理学 + LLM，结合词根词缀给出可执行建议
- **独家写法**：与"AI 报告"对比，错题分析聚焦个体问题

#### P0-6：Vercel Edge Function + CORS 跨域
- **文件**：[api/ai-report.js:30-47](D:/claude%20code/HappyEnglish/api/ai-report.js#L30-L47)
- **架构**：Vercel Edge Function 接收前端请求，转发到 MiniMax API
- **设计动机**：隐藏 API Key、统一错误处理、CORS 预检
- **独家写法**：解释为什么必须用 Edge Function 而非直接前端调用
